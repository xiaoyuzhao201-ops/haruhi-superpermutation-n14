# 14 符号超排列：将公开见证再缩短一个字符

这份材料不是最短性证明。它构造了长度 **93,904,752,506** 的 14 符号超排列，较源词 W-0117（93,904,752,507）少 1。公开下界为 93,891,141,150，仍差 13,611,356。

源词是 Jay Pantone 的 [W-0117](https://superpermutations.com/w/W-0117)，数据按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 使用。本见证交换了源词的两个内部相邻长段并改写了三处接缝。源词覆盖由 Almanac 的公开校验记录提供；这里另外用精确的保留窗口论证验证改动，不宣称对新词做过 87,178,291,200 种排列的独立全量重扫。全部新实验在云电脑上完成。

## 接缝证书

按源词顺序编号 i、j、k。p 是左端完整 14 字符排列的起始位置（从 0 开始），右端起点是 p 加旧接缝费用。

| 缝 | p | 左排列 | 右排列 | 旧费用 |
|---|---:|---|---|---:|
| i | 8,018,599,985 | DCB015342A9876 | 0173426985ABCD | 14 |
| j | 36,587,897,101 | D1C02B459A3768 | 768234519ABCD0 | 11 |
| k | 50,281,547,842 | 0DC1B896425A37 | A37689B5214CD0 | 11 |

在每个接缝处，左块保留左排列的全部 14 字符，右块从右排列第一个字符开始。这样分成四块 A、B、C、D，相邻块在原词中允许重叠。任何不整段落在某一保留块内的原 14 字符窗口，其起点必严格介于上述某一对端点起点之间。两套独立解析确认，这 33 个中间窗口全部不是排列。

改按 A、C、B、D 顺序，按最长重叠拼接。三处新缝是 i→j、k→i、j→k，费用依次 12、14、9，合计 35（旧 36）。四块的内容都原样保留，故所有原有排列仍出现；因此覆盖 14! = 87,178,291,200 种连续排列。重复窗口不影响论证。详细中间窗口和 token 改动见 splice.json。

## 文件

- n14-93904752506.detour：新词的 [Detour 格式](https://superpermutations.com/format.txt) 完整压缩表示，不是截断文本。
- W-0117.detour：公开源词。详见 source.json 的归属、许可证和原始核验元数据。
- verify.sh：验证源文件指纹，并逐字节检查新 Detour 的 token 流是否等于证书指定的拼接。加环境变量 CHECK_FULL_HASH=1 可重算两词解码文本的完整 SHA-256；只流过文字，不写出约 94 GB 的全文。需要 Python 3、xz 和常规 shell 工具；全文哈希另需支持 SSSE3 的 C++ 编译器与 OpenSSL 开发库。
- cutscan.cpp、reorder.cpp、reorder_exact.log：从公开词提取允许切开的接缝，并排查三切交换。
- lower/：七符号法向 n=14 的迁移试验。枚举到 **23 行、2 孔、297 个互异旋转类** 的 n=14 链，反驳把 n=7 容量上限直接改成 12+2a 的类推。这些有限搜索并未提高全局下界。

复跑搜索：xz -dc W-0117.detour > base.tokens；编译 g++ -O3 -std=c++20 cutscan.cpp -o cutscan，以及 g++ -O3 -std=c++20 -pthread reorder.cpp -o reorder；运行 ./cutscan base.tokens > cuts.csv，然后 ./reorder cuts.csv 192 8 0 5 exact3。
